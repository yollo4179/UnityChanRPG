# 팝업 입력 차단과 Event_EnterArea 로그 (2026-09-29)

## 원인

`UIManager`는 열린 팝업을 스택으로 관리하지만 플레이어 상태, 이동 컴포넌트, 카메라는 스택을 확인하지 않았다. 따라서 팝업 위를 클릭하거나 팝업이 열린 채로 키를 누르면 캐릭터 공격·스킬·이동과 카메라 회전이 계속 실행됐다. 이미 시작한 공격은 코루틴이 유지됐고, 상태 종료 시 새 열거자를 `StopCoroutine`에 전달해 실제 실행 중인 코루틴을 정지시키지 못했다.

`NavMeshKeys`는 플레이어가 구역에 들어갈 때마다 `Event_EnterArea`를 발행한다. 이 이벤트는 수락된 `VISIT_AREA` 퀘스트의 현재 단계에서만 구독한다. 해당 단계가 없으면 구독자가 없는 것이 정상인데, `EventManager.Publish`가 이를 오류처럼 로그에 출력했다.

## 적용

- `UIManager.BlocksAttackInput`은 일반 팝업에 포커스가 있거나 모달·UI 드래그·텍스트 입력 중일 때 참이다. 인벤토리·장비·스킬북·퀘스트 창의 포커스를 월드 클릭으로 해제하면 창은 유지되고 다음 클릭부터 공격할 수 있다. HUD만 표시 중이면 공격할 수 있다.
- `UIManager.BlocksGameplayInput`은 일반 팝업에 포커스가 있거나 모달·UI 드래그·텍스트 입력 중일 때 참이다. 대화·상점·아이템 상세·거래 확인·강화·향후 ESC/설정 메뉴 같은 모달은 월드 클릭으로 해제되지 않는다. 중력과 착지 처리는 계속 실행한다.
- 공격·스킬 중 공격 차단 상태가 되면 실행 중인 상태를 종료하고, 코루틴·이펙트·히트박스를 정리한다. 모달 진입 시에는 대시도 종료한다. 차단 중 새 공격 이벤트와 투사체 생성도 막는다.
- `UI_Draggable_Move`는 드래그 시작·종료·비활성화 때 UIManager에 상태를 알린다.
- UI 위 클릭은 기본 공격으로 처리하지 않는다. 팝업 닫기 클릭도 버튼을 놓을 때까지 공격으로 이어지지 않는다.
- 일반 팝업에 포커스가 있으면 첫 월드 클릭은 선택 해제에 사용한다. 선택된 항목이 일반 버튼이면 같은 클릭으로 공격할 수 있고, 입력창이나 그 밖의 포커스 상태였다면 버튼을 놓을 때까지 게임 입력을 막는다.
- `OnSkill`은 Animator의 Trigger 매개변수이므로 근접·원거리 스킬에서 `SetTrigger`를 사용한다.
- 이벤트 구독자가 없을 때 `Publish`는 조용히 종료한다. 구역 이벤트를 수락된 퀘스트 단계가 구독하면 기존처럼 전달한다.

## 검증

`dotnet build Assembly-CSharp.csproj --no-restore -v:q -clp:ErrorsOnly`: 오류 0개. 관련 파일의 `git diff --check`: 통과. Unity 플레이 모드에서 일반 창을 연 채 월드 클릭, HUD 클릭, 드래그, 모달의 이동 차단, 팝업 닫기 클릭, 수락 전후의 방문 퀘스트 구역 진입은 추가 확인이 필요하다.

## HUD 팝업 단축키

HUD 아이콘의 팝업 매핑을 키보드에도 연결했다. **I 인벤토리, Q 퀘스트, E 장비, K 스킬창**이다. 화면 버튼과 단축키는 같은 열기/닫기 함수를 사용하고, 열린 창은 같은 키로 다시 닫을 수 있다. 카메라 초기화 키는 `Home`이다. C# 빌드와 단축키 매핑 검사는 통과했으며 실제 게임 화면에서 각 키의 동작은 확인이 필요하다.
