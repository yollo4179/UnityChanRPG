# 월드 클릭으로 UI 포커스 해제 (2026-09-29)

## 요구와 원인

기존에는 일반 팝업의 열림 여부를 공격·카메라 차단 기준으로 사용했다. 인벤토리 등의 창을 켜 둔 채 월드로 돌아갈 수 없었고, `EventSystem`의 선택 상태와 팝업의 포커스 상태도 분리되지 않았다.

## 적용

- `UIManager`가 가장 최근에 상호작용한 일반 팝업을 포커스 대상으로 기억한다. 팝업을 열거나 팝업 안을 클릭하면 포커스를 얻는다.
- 좌클릭 시 `EventSystem.RaycastAll`의 UI 그래픽 결과로 UI 클릭 여부를 먼저 판단한다. UI 클릭은 공격으로 이어지지 않는다.
- 월드를 클릭하면 `EventSystem.currentSelectedGameObject`와 일반 팝업 포커스를 해제한다. 팝업 GameObject는 닫지 않는다.
- 선택된 대상이 `TMP_InputField`/`InputField`이거나 일반 버튼 이외의 팝업 포커스라면 첫 월드 클릭은 해제에만 사용한다. 마우스 버튼을 놓은 다음 클릭부터 공격한다. 일반 버튼만 선택돼 있으면 같은 클릭에 공격할 수 있다.
- 모달이 열렸거나 드래그 중이면 월드 클릭으로 포커스를 해제하지 않는다. 포커스가 유지되는 동안 이동·공격·스킬·카메라 입력을 막는다.
- 동일 프레임에 플레이어와 카메라가 같은 클릭 판정을 사용하도록 처리 결과를 프레임 단위로 저장한다. 포인터 이벤트 데이터와 레이캐스트 목록을 재사용한다.

## 확인

`dotnet build Assembly-CSharp.csproj --no-restore -v:q -clp:ErrorsOnly`와 `git diff --check`로 정적 검증한다. 실제 Unity 플레이 모드에서는 다음 흐름을 확인해야 한다.

1. I/Q/E/K로 창을 열어 이동·공격·스킬·카메라가 제한되는지 확인한다.
2. 창을 연 채 월드를 클릭해 창은 남고 선택만 풀리는지, 첫 클릭에는 공격하지 않고 다음 클릭에 공격하는지 확인한다.
3. 버튼 선택 뒤 월드 클릭은 선택 해제와 공격이 같은 클릭에 되는지 확인한다.
4. 텍스트 입력 중 첫 월드 클릭은 입력 포커스만 해제하고 공격하지 않는지 확인한다.
5. 모달과 드래그 중 월드 클릭이 포커스를 해제하지 않는지 확인한다.
